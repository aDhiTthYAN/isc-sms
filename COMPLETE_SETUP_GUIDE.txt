## UNDERSTANDING THE SYSTEM FIRST
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Your app has TWO separate systems that must match each other:

  SYSTEM 1 — Firebase Authentication
  → This handles LOGIN (email + password)
  → Think of it as the LOCK on the door

  SYSTEM 2 — Firestore Database (staff collection)
  → This stores WHO the person IS (name, role)
  → Think of it as the NAME TAG after they enter

WHY BOTH ARE NEEDED:
  Authentication says "yes this person can log in"
  Firestore says "this person is the CEO" or "this person is staff"

  Without Authentication → can't log in at all
  Without Firestore record → logs in but app shows blank/error

WHY THE DOCUMENT ID = UID:
  When someone logs in, Firebase gives them a unique ID called UID
  The app uses that UID to find their profile in Firestore
  So the Firestore document ID MUST equal their Authentication UID
  That's how the app connects login → role → correct dashboard

## PART 4 — SET UP FIRESTORE SECURITY RULES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

This allows your app to read and write data properly.

  1. Go to Firebase Console → Firestore Database
  2. Click the "Rules" tab at the top
  3. Delete everything in the rules editor
  4. Paste this exactly:

    rules_version = '2';
    service cloud.firestore {
      match /databases/{database}/documents {
        match /{document=**} {
          allow read, write: if request.auth != null;
        }
      }
    }

  5. Click "Publish"

## PART 9 — HOW EMAIL NOTIFICATIONS WORK
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The app has TWO notification systems:

  SYSTEM 1 — In-App Bell (works immediately, no setup needed)
  → Bell icon in top right corner
  → Shows red badge with unread count
  → Staff sees it instantly when CEO assigns something
  → Works as soon as you run the app

  SYSTEM 2 — Email Notifications (needs EmailJS setup)
  → Staff gets an actual email to their inbox
  → Setup takes 10 minutes, completely free

  HOW TO SET UP EMAIL NOTIFICATIONS:

  1. Go to https://www.emailjs.com
  2. Click "Sign Up Free"
  3. After signup → click "Add New Service"
  4. Choose Gmail → connect your Gmail account
  5. Copy the "Service ID" shown (looks like: service_abc123)

  6. Click "Email Templates" → "Create New Template"
  7. Template name: Task Assigned
  8. Subject: New Task Assigned to You
  9. Body:
       Hi {{to_name}},
       {{assigned_by}} has assigned you a new task.
       Task: {{task_title}}
       Priority: {{priority}}
       Due Date: {{due_date}}
       Open the dashboard: {{app_url}}
  10. Click Save — copy the Template ID (template_task_assigned)

  11. Repeat for Follow-Up template:
       Subject: Follow-Up Required — {{student_name}}
       Body:
       Hi {{to_name}},
       {{assigned_by}} has assigned a follow-up for {{student_name}}.
       Instructions: {{note}}
       Priority: {{priority}}
       Open the dashboard: {{app_url}}
  12. Save — Template ID: template_followup_assigned

  13. Click your profile icon (top right) → copy "Public Key"

  14. In VS Code open: src → firebase → emailService.js
  15. Replace these two lines:
       const SERVICE_ID = 'YOUR_EMAILJS_SERVICE_ID';
       const PUBLIC_KEY = 'YOUR_EMAILJS_PUBLIC_KEY';
  16. With your real values:
       const SERVICE_ID = 'service_abc123';
       const PUBLIC_KEY = 'user_xyz789abc';
  17. Press Ctrl+S to save

  Now when CEO assigns a task, staff gets an email instantly.

## COMMON PROBLEMS AND FIXES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

PROBLEM: "Invalid email or password" after login
FIX:
  → Go to Firebase → Authentication → Users
  → Make sure the email exists there
  → Make sure the UID in Firestore matches exactly
  → Check Firestore collection is named "staff" (lowercase)

PROBLEM: Login works but shows blank dashboard
FIX:
  → Go to Firestore → staff collection → your document
  → Make sure "role" field value is exactly: ceo (lowercase)
  → Make sure "active" field is boolean true (not string "true")

PROBLEM: Staff logs in but sees CEO data
FIX:
  → Check Firestore → staff → their document
  → role must be: staff (not Staff, not STAFF)

PROBLEM: npm run dev gives error
FIX:
  → Make sure Node.js version is 20 or higher
  → Run: node --version
  → If below 20, download new version from nodejs.org
  → Then: npm install and npm run dev again

PROBLEM: "Permission denied" error in browser console
FIX:
  → Go to Firestore → Rules tab
  → Make sure rules allow read/write for authenticated users
  → Paste the rules from Part 4 above and publish

## QUICK REFERENCE — ROLE PERMISSIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  CEO (role: "ceo")
  ✅ Full access to everything
  ✅ Add / remove / manage staff
  ✅ See all students across all staff
  ✅ Assign tasks to any staff member
  ✅ Assign follow-ups to any staff member
  ✅ See all daily reports
  ✅ Lead pipeline, financial data
  ✅ Revoke staff access

  ADMIN (role: "admin")
  ✅ Manage students — add, edit, bulk import
  ✅ Manage batches
  ✅ View and resolve concerns
  ✅ Upload documents
  ✅ View reports submitted by staff
  ❌ Cannot manage staff members
  ❌ Cannot see lead pipeline

  STAFF (role: "staff")
  ✅ See only their assigned students (e.g. 100 students)
  ✅ View their batch and all students in that batch
  ✅ Log follow-up notes on their students
  ✅ Complete tasks assigned to them
  ✅ Submit daily reports
  ✅ View student leaderboard
  ❌ Cannot see other staff's students
  ❌ Cannot add or delete students
  ❌ Cannot assign tasks
